# Data sources

The first adapter uses the [official USGS earthquake catalog API](https://earthquake.usgs.gov/fdsnws/event/1/) with its [GeoJSON schema](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php). No scraping or API key is involved. Source metadata is centralized in `UsgsEarthquakeProvider.metadata()`; transport configuration is bound through validated `UsgsProperties`.

Queries specify coordinates, radius, explicit UTC start/end, earthquake type, newest-first ordering, and a 201-feature probe for the 200-event application limit. HTTP 204 and a valid empty FeatureCollection are no-data results. Malformed records fail the whole query rather than silently underreporting coverage. Non-earthquake records are ignored, and repeated source IDs are deduplicated. Responses are capped at 2 MB, with configurable connect/read timeouts and no automatic retries. Read timeout is a socket inactivity timeout, not a whole-request deadline.

Credit: **U.S. Geological Survey**. USGS-produced information is generally U.S. public domain, while marked third-party material can have separate rights. Follow the [USGS copyright and credit policy](https://www.usgs.gov/information-policies-and-instructions/copyrights-and-credits); do not imply endorsement. Source evidence URLs are retained on every observation.

Catalog data may be revised. This milestone queries on demand, has no polling schedule or cache, and records both retrieval and source-update timestamps. USGS recommends its summary feeds for repeated display workloads; those feeds update every minute. The catalog endpoint is used here for bounded spatial/time searches. A future global map refresh should use shared feeds/caching rather than repeated per-marker queries.

GeoJSON coordinates are longitude, latitude, depth; the adapter maps them explicitly. Magnitude and depth are measurements, not a scientific location-risk model. USGS event flags and PAGER labels are not converted into Custerra warnings, tsunami events, confidence or arbitrary severity. No earthquake prediction is claimed.

Live observations are not automatically inserted into the stored hazard table. Persistent ingestion, event revision/deletion handling and refresh scheduling remain separate work; existing database APIs retain their stored-data contracts.


The frontend additionally uses OpenStreetMap as a basemap, with visible attribution and deployment-configurable tile URLs. Basemap content is not hazard evidence. No offline or bulk tile fetching is implemented; see [frontend map-provider details](frontend.md).


## Open-Meteo — Milestone 7

The weather adapter uses the [official forecast API](https://open-meteo.com/en/docs) for current temperature at 2 m, rain, total precipitation and wind at 10 m. Current conditions are weather-model output. Requested units are Celsius, millimeters and kilometers/hour; timestamps are Unix seconds in GMT. Rain and precipitation refer to the returned preceding aggregation interval, not a daily total. The UI retains model grid coordinates, validity time, retrieval time and source credit.

The [Open-Meteo terms](https://open-meteo.com/en/terms) distinguish data licensing from API access: data is CC BY 4.0 with attribution, while the default free API is for non-commercial use and subject to usage limits. Commercial deployment requires an appropriate service arrangement or replacement provider. This adapter does not yet support paid API credentials. The frontend displays linked Open-Meteo credit and the license.

`OPEN_METEO_URL` defaults to `https://api.open-meteo.com/v1/forecast` and must be HTTPS without credentials, query or fragment. Connect/read timeouts default to 3/10 seconds and are configurable from 100 to 30,000 ms. Responses are capped at 64 KiB; no automatic retry, cache, scheduled refresh or persistence is implemented. Read timeout bounds socket inactivity, not the entire request. Requests occur on submitted location selections and manual retry; use shared caching and request budgeting before scaling usage.

Missing measurements remain null and set `partial`. Conditions older than two hours set `stale`; this is an application display threshold, not a scientific hazard boundary. Invalid envelopes, units or values fail the request rather than becoming an empty success. This milestone adds environmental context only; no weather-derived hazard score or warning is inferred.


## Historical and journey queries

Milestone 8 uses the same USGS catalog with a minimum magnitude and explicit historical dates, a 2,001-record probe and a 2 MB response cap. Immutable snapshots preserve revisions as retrieved. Route queries retain the recent 200-event limit; truncation suppresses monitoring notices. Opt-in journey scheduling triggers bounded on-demand catalog requests; no shared provider cache or global feed ingestion is added. See [history and journeys](history-and-journeys.md) for coverage and refresh behavior.

## Milestone 12 — NASA FIRMS

The connected product is **VIIRS Suomi NPP near-real-time thermal-anomaly observations**, via the [FIRMS Area CSV API](https://firms.modaps.eosdis.nasa.gov/api/area/). It requires `FIRMS_MAP_KEY` in the backend environment. Never put it in `NEXT_PUBLIC_*`. An absent key produces `UNAVAILABLE / NOT_CONFIGURED`; it is not an empty successful observation set. The key-bearing URL is never included in response metadata or propagated exceptions. The hostname and product are fixed in the adapter. The properties object's string representation redacts the key.

Requests use a spherical bounding envelope, split at the antimeridian, followed by exact distance filtering. Pole-reaching circles request all longitudes. This initial adapter makes at most two requests and requests at most five UTC calendar dates, the Area API's documented per-call maximum. Longer requested windows are explicitly `PARTIAL`, with actual requested dates in limitations. This also applies to a rolling five-day query if it spans six calendar dates. Only one VIIRS product is connected; this is not complete satellite, fire, or real-world hazard coverage. Clouds, sensor resolution, overpass timing and processing delays apply.

Rows retain acquisition date/time as `observedAt` and `startedAt`; `retrievedAt` is separate. `sourceUpdatedAt` is null because the CSV does not supply a revision timestamp. Brightness (`bright_ti4`, `bright_ti5`, kelvin), radiative power (`frp`, MW), scan/track (km), satellite, instrument, raw confidence, processing version and day/night metadata remain available. VIIRS l/n/h confidence maps to LOW/MEDIUM/HIGH; unrecognized confidence remains UNKNOWN. This is detection confidence, not confidence that a wildfire threatens a location. Severity remains UNKNOWN. Information type remains the existing `OBSERVED_EVENT` value. Every detection is titled **Satellite-detected thermal anomaly**, never automatically a confirmed wildfire.

FIRMS does not supply incident IDs in this CSV. The adapter derives a stable row identity from product, satellite, instrument, acquisition instant and numeric coordinates, documenting that method in attributes. Repeated rows and measurement revisions share identity; distinct overpasses or pixel coordinates do not. This identity is not a grouped fire incident. Responses are capped at 2 MB per request and 20,000 parsed rows; overflow fails the source. Up to the newest 500 spatially/time-matching observations are returned, with `truncated=true` on overflow. Rejected rows yield PARTIAL coverage with a rejection count; malformed envelopes fail the source. HTTP errors and timeouts are sanitized. There are no automated retries or background ingestion.

**Attribution and use:** acknowledge NASA FIRMS/LANCE and VIIRS Suomi NPP. Consult [NASA Data Use and Citation Guidance](https://www.earthdata.nasa.gov/engage/open-data-services-software/data-use-policy) and linked dataset-specific citation/disclaimer obligations before commercial redistribution. NASA's open-data guidance does not confer rights to suggest NASA endorsement; dataset-specific restrictions still apply. Preserve source links and disclaimers when redistributing. The API advertises 5,000 transactions per 10-minute window; large requests can cost multiple transactions. Recheck terms and quotas before scaling. NRT is tied to satellite acquisition and processing, not a fixed guaranteed refresh interval; RT/URT observations may be replaced. Live FIRMS verification is explicitly pending at the user's request; standard tests use synthetic fixtures only.

## Milestone 12 — GDACS

The adapter reads the public [GDACS recent-event RSS feed](https://www.gdacs.org/xml/rss.xml), linked from the [official feed reference](https://www.gdacs.org/feed_reference.aspx). It supports source types EQ, TC, FL, VO, TS and WF. Other categories are counted as rejected/unsupported and never relabeled. `GDACS_ENABLED=false` reports UNAVAILABLE; default is enabled. The recent feed is **always PARTIAL** for a user-selected time window because it is not an exhaustive historical catalog. Point events are filtered by start time; interval events can overlap the requested window. Spatial filtering uses the representative point only.

The XML parser forbids DOCTYPE, external entities, external DTD/schema access and XInclude. Responses are bounded to 4 MB and 1,000 examined items. Malformed XML fails the provider; invalid/unsupported individual items are counted in coverage limitations. Green/orange/red map to LOW/MODERATE/HIGH *source event severity*, retaining the raw color and alert score. Missing/unrecognized classifications remain UNKNOWN. Confidence remains UNKNOWN. Information type is **ADVISORY**, never an automatically promoted official local warning. GDACS colors describe modeled potential humanitarian impact, not measured danger at a user's coordinates.

Identity is GDACS + event type + event ID; episode IDs and provider version stay in attributes. Newer source-modified timestamps win within the same identity. Country, ISO3 and source bbox are retained when supplied. A GDACS bbox is a map extent; it is **not** treated as a validated affected-area polygon or used to derive an affected radius. `fromdate`, `todate`, `datemodified`, acquisition/retrieval timestamps and source report links remain available. No cross-provider incident correlation is claimed. A feed publication time more than two hours old adds `STALE_FEED`; the threshold is operational, not scientific.

**Attribution and use:** show “Global Disaster Awareness and Coordination System, GDACS”. The [official API quick start](https://www.gdacs.org/Documents/2025/GDACS_API_quickstart_v2.pdf) describes free data access and requests source acknowledgement. The live feed's resource acknowledgement specifies European Union CC BY 4.0 with GDACS credit; that does not imply every linked third-party resource has identical rights. Preserve attribution, indicate transformations and review resource-specific restrictions before redistribution/commercial use. [GDACS terms](https://www.gdacs.org/About/termofuse.aspx) explain automated impact estimation, uncertainty, lack of timeliness/completeness guarantees and the need to confirm results with competent authorities. The feed reference states updates approximately every six minutes. No numeric rate limit is published in that reference; no unlimited-use assumption is made. Custerra retrieves on demand with no retries or scheduled GDACS polling. Shared caching/request budgets remain a deployment prerequisite.

Both new adapters default to 3-second connect and 10-second read timeouts, configurable in the same 100–30,000 ms range as USGS. Read timeout limits inactivity, not total end-to-end duration. Nearby requests currently call selected providers sequentially, so worst-case latency adds across providers; narrow with `provider` when debugging. A browser timeout does not mean no hazards exist.

## Milestone 13 — Place search and driving geometry

`GeocodingProvider` uses [Open-Meteo's geocoding API](https://open-meteo.com/en/docs/geocoding-api), with GeoNames attribution. It returns up to five candidate cities/places; users must select a candidate. This is not guaranteed street-address geocoding. Requests occur only on an explicit search button, never on every keystroke. `GEOCODING_URL` is replaceable deployment configuration. The free default is non-commercial, subject to [Open-Meteo terms](https://open-meteo.com/en/terms); GeoNames attribution/data licensing also apply. Search responses preserve retrieval time and are cached for 24 hours, at most 200 queries per process. There is no provider update guarantee. Avoid sending confidential place searches to public services.

`RouteProvider` uses the [FOSSGIS OSRM driving endpoint](https://routing.openstreetmap.de/about.html), configurable with `ROUTING_URL`. This initial adapter supports DRIVING only. It requests full polyline6 geometry (not a straight-line approximation), road distance and duration. Full geometry is decoded only for analysis and map rendering; API output retains the compact encoded form instead of repeating thousands of raw coordinates. Bounds: 1 MB provider payload, 200,000 encoded characters, 20,000 vertices, road distance at most 900 km and endpoint snapping at most 5 km. NoRoute, excessive length or excessive snapping returns 422. Supplied/manual waypoint assessment retains its original 20-point contract.

OSRM attribution includes OpenStreetMap contributors, provider terms and a “Fix the map” link. OSM data is ODbL; derived/redistributed databases can carry attribution/share-alike duties. The public routing server requires an identifying User-Agent, at most one request per second, no scraping or heavy use. The adapter identifies Custerra; the planning service enforces one start per second per JVM and rejects excess with 429. This is sufficient only for the current single-instance prototype: production/multiple instances require a shared budget and an appropriate self-hosted or commercial provider. The free demo is not a commercial production SLA. Routing data is refreshed roughly every two days, subject to processing delay; duration does not incorporate live traffic, hazard impacts or arrival-time forecasts. No routing results are automatically persisted or reused for subsequent hazard evidence.

Planning transport defaults to 3-second connect / 10-second read timeouts, without automatic retries. HTTP errors and malformed responses use the existing 502/504 contract. Only successful geocoding results are cached. Place and route metadata is separate from hazard observations; provider geometry is not proof that a road is open or safe.

## Research-only historical dataset

Milestone 18 retains the attributed UCI Algerian Forest Fires CSV under CC BY 4.0. It is a fixed historical research dataset, not a live hazard feed. Source, checksum, exclusions, split design and reuse limitations are documented in [the research model card](ml.md).
